入门

开始之前

MacAI 是一个跑在 Apple Silicon Mac 上的本地 AI 运行管理系统。你把 LLM、语音识别（STT）、语音合成（TTS）模型导入进来，它在本机用 Metal / MLX / Core ML 加速完成推理，并按 OpenAI 兼容格式对外提供服务——数据不出这台 Mac，断网也能用。

所有功能都经由一个本地守护进程 aiworkd（默认 127.0.0.1:11435）提供。三种客户端连的都是它：

客户端适合说明
MacAIConsole（GUI）日常使用SwiftUI 原生应用：引擎安装、模型下载注册、任务与日志观测、设置。本文以它为主线。
macai CLI脚本与远程 SSHRust 命令行，覆盖全部模型生命周期操作，见 macai 命令行。
OpenAI SDK / 任意 HTTP 客户端接入第三方应用CherryStudio、Hermes 等，把 base_url 指到本机即可，见 HTTP API。
先说清楚边界：项目处于活跃开发阶段，适合本地开发、实验与个人工作流，目前无法承诺 API 稳定性和跨版本兼容。要放在生产环境的话，建议锁定版本并自测。
入门

系统要求

  • Apple Silicon Mac（M1 及之后）
  • macOS 14 或更高版本

用 DMG 安装包就只有这两条：应用自包含 aiworkd、macai、uv 和全部 Runner 适配器，不需要预装 Rust 或 Python。

从源码构建额外需要：

  • Rust stable toolchain
  • Xcode Command Line Tools
  • CMake（brew install cmake）——只有编译 whisper.cpp 引擎时用到
  • Python 3.12（构建与测试环境使用；Python 系列 Runner 的运行环境由内置 uv 自行管理，不依赖系统 Python）

仓库与安装包都不包含模型权重。所有模型在首次使用时下载，或从你已有的本地文件导入。

入门

安装

方式一：DMG 安装包（推荐普通用户）

  1. 从 GitHub Releases 下载 MacAIConsole.dmg，打开后把 MacAIConsole.app 拖入「应用程序」。
  2. 首次打开可能被 Gatekeeper 拦截（应用未签名）。两种处理任选： 
    # 终端清除隔离标记
xattr -cr /Applications/MacAIConsole.app
    或者到「系统设置 → 隐私与安全性」，滑到最下方「安全性」区域点「仍要打开」。
  3. 启动应用即可。它内置的 aiworkd 会随之拉起，无需任何命令行操作。

方式二：从源码构建（开发者）

git clone https://github.com/GuanXuzeng/MacAI.git
cd MacAI
cd apps/MacAIConsole
scripts/build-app.sh release

该脚本会联动编译后端和 GUI、组装应用并直接拉起。开发调试也可以在 apps/MacAIConsole 下直接 swift run；此时需先自行构建并启动 daemon。打 DMG 用 scripts/build-app.sh dmg，产物在 apps/MacAIConsole/build/。

daemon 由谁启动？GUI 启动时会自动按顺序探测并拉起：AIWORKD_PATH 环境变量 → 仓库 target/release/aiworkd → target/debug/aiworkd。也可以完全不用 GUI，手动 ./target/release/aiworkd 后只用 CLI 和 API。
入门

五分钟跑通

下面用推荐的 MiniCPM5 2B（MLX 4-bit，约 2.5 GB）走通第一条链路。STT / TTS 的流程完全一样，只是换一个引擎和模型。

  1. 装引擎。打开 MacAIConsole，侧边栏进「管理」页。顶端「引擎」区找到 mlx-lm，点「安装」。Python 依赖由内置 uv 自动部署，不需要你装 Python。
  2. 下模型。在「管理」页推荐模型卡片里找到 MiniCPM5 2B MLX 4-bit，点「下载」。daemon 在后台断点续传，完成后自动注册。网络慢的话，先去「设置 → 模型下载源」切到 hf-mirror.com。
  3. 加载。模型卡片上点「启动」，等状态变为常驻（resident）。「运行状态」页能看到它占用的内存和加速设备。
  4. 验证。用 CLI 或 OpenAI 兼容 API 发起请求；完成后可在 GUI「任务」页查看记录： 
    # ① CLI
macai chat MiniCPM5-2B-MLX-4bit "用一句话介绍你自己"

# ② OpenAI 兼容 API
curl http://127.0.0.1:11435/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"MiniCPM5-2B-MLX-4bit","messages":[{"role":"user","content":"Hello"}]}'

跑通了就继续看 控制台导览 和 模型获取与注册；哪一步卡住了直接翻 故障排查。

日常使用

控制台导览

MacAIConsole 主界面。GUI 是无状态客户端，界面上每个数字都实时来自 daemon。

页面能做什么
运行状态daemon 版本与 PID、内存预算、系统内存压力折线（5 分钟滑动窗口）、活跃请求、已加载模型的常驻内存与加速设备。模型条目点进去是详细设置。
任务当前运行与最近完成的 Chat / STT / TTS 请求，含耗时、输入输出与错误。推理模型的思考过程与最终回答分开显示。
管理本文档的核心页面，见下两节：引擎与 Runner、模型获取与注册。
日志GUI 与 daemon 双端日志，默认 Info，可开 Debug，按级别着色；「在访达中显示」直接打开日志目录。
设置外观（跟随系统 / 明亮 / 暗黑）、自动拉起 daemon、内存预算、网络代理、模型下载源、恢复已忽略的引擎与推荐模型、检查更新（关于）。

菜单栏常驻图标可以快速查看 daemon 状态并启停。任务历史是有界的：终态任务保留最近 100 条。

日常使用

引擎与 Runner

每个推理引擎都是一个独立的 Runner 进程（以 org.macai.* 命名），由 daemon 统一安装环境、装配与监控。某个引擎崩溃不会拖垮 daemon——客户端拿到的是 backend_crashed 这类结构化错误，其他模型继续服务。

安装与卸载

在「管理」页顶端按 LLM / STT / TTS 分组点「安装」即可；也可以直接调 API：

curl -X POST http://127.0.0.1:11435/api/runners/org.macai.mlx-lm/install

已就绪的引擎在右键菜单里可以卸载受管环境和引擎文件，之后能重装。正在使用该引擎的模型要先卸载。如果本机已有同版本引擎二进制，可以用环境变量跳过下载：MACAI_LLAMA_SERVER、MACAI_WHISPER_SERVER（绝对路径）。

新建自己的 Runner（Script Runner）

「管理」页的「新建 Runner」可以从 Chat / STT / TTS 模板编辑一个带 PEP 723 元数据的 .macai.py 单文件。内置编辑器带语法高亮和依赖助手：推理库从预设里选，或直接粘贴官方 pip install / uv add 命令；也可以导入本地 .py（覆盖前有确认），或一键复制一段完整的 Prompt 交给外部 AI 帮你生成脚本。保存时 daemon 会静态检查依赖与权限，在临时环境完成 lock、sync 和导入探针，通过后作为标准 Runner 保存到 Plugins/<runner-id>/，重启 aiworkd 后即可像内置 Runner 一样注册模型。

信任边界：Runner 以 aiworkd 的用户权限运行本地代码，digest 校验和环境变量白名单不构成操作系统沙箱。只安装你读过或信得过的脚本。单文件示例可以参考仓库 samples/ 下的 Hojo-TTS-Light。

推荐模型在「管理」页点「下载」即可，daemon 自动下载（断点续传）并注册。对某条引擎或推荐模型不感兴趣，右键忽略即可，设置页可以恢复。

三种获取模型的方式

  1. 推荐模型一键下载：如上，最省事。
  2. 「添加模型」远端下载：输入公开 Hugging Face 或 ModelScope 的仓库 ID / URL，预览文件与大小后勾选下载到模型仓库。下载不会自动注册或加载，完成后需手动启动。
  3. 导入本地已有模型：GGUF / whisper .bin 单文件直接在「添加模型 → 本地文件」导入；MLX 等目录型模型放进对应子目录后注册（或用 CLI macai load）。目录约定在 数据、日志与内存。

注册语义：这些规则先知道，能少踩坑

  • 目录型模型（MLX、sherpa-onnx、Qwen3 等）模型 ID 必须与目录名一致；GGUF / .bin 单文件没有这个限制。
  • daemon 用目录签名静态探测模型属于哪个 Runner。识别不了的目录会直接拒绝注册，提示检查模型是否下载完整，或安装 / 新建对应 Runner——不会瞎猜。CLI 上可用 macai inspect <目录> 先看诊断。
  • 显式 --provider 是硬选择：指定的 Runner 不可用就报错，绝不静默换成别的。注册时的选择结果（requested / selected / 理由 / 有效设备）会被持久化记录，可在 API 返回里审计。
  • LLM 注册默认上下文 4096，可在详情设置调整；默认采样参数 temperature 1.0、top_p 0.95 同样可改。

生命周期：load / start / unload / remove / rename

操作作用磁盘文件
load（注册并加载）新模型注册进 SQLite 注册表并立即加载不动
start把注册表中已有模型加载进内存不动
unload停 worker、释放内存；注册记录保留不动
remove只删注册记录保留，可重新注册
rename改 ID，运行中的模型先安全停止不动

卸载请求不会打断进行中的推理——请求期间模型挂着 lease，手动卸载、LRU 逐出和空闲回收都要等它释放。由推荐模型 Profile 绑定创建的模型 ID 是固定的，不支持 rename。

驻留与内存

「启动」≠ 永久占内存。每个模型有 keep-alive 空闲驻留策略（0 / 5m / 2h / always），到点无人使用就自动卸载；内存紧张时 daemon 按 LRU 逐出。daemon 的内存预算默认 min(RAM×0.75, RAM−8GB)，设置页可改，也可用 AIWORKD_MEMORY_BUDGET（字节）覆盖。跑大模型前先看看预算还剩多少。

三大能力

对话 Chat

GUI

通过 CLI 或 API 发起 Chat 请求后，「任务」页会记录运行状态与结果；推理模型（如 DeepSeek 系）的思考过程单独分区展示，不与最终回答混在一起。模型的默认采样参数在运行状态页的模型详情里调整，右键「使用示例」会带上这三个参数生成现成的 API 代码。

CLI

# 一次性提问（无上下文记忆）
macai chat local-model "Hello" --system "Answer concisely" --temperature 0.2

# 交互式多轮对话（带上下文记忆），Ctrl-D 退出
macai run local-model --max-tokens 256

API

标准 POST /v1/chat/completions。"stream": true 时逐 token SSE 推送，以 data: [DONE] 结束；省略 temperature / top_p 时使用模型注册时保存的默认值。

推理模型会通过 reasoning_content 字段返回思考内容，最终回答仍在 content；非推理模型没有该字段。请求带可选 session_id（不透明字符串）可声明多轮延续：两个 LLM Runner 都依托常驻 worker 复用对话前缀的 KV 缓存，长历史下首 token 延迟明显下降。

一个诚实的怪癖：Metal 数值精度差异可能使缓存命中后 temperature=0 的输出与全量重算偶发不同。要严格可复现的实验，别依赖 session_id 复用。

Python SDK 接入：

from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:11435/v1",
    api_key="local",  # daemon 无鉴权，占位即可
)

resp = client.chat.completions.create(
    model="MiniCPM5-2B-MLX-4bit",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
三大能力

语音识别 STT

上传 wav / mp3 / flac / ogg / m4a 都可以，daemon 在入口统一解码为 PCM WAV 再交给 Runner，所以各 Runner 对格式的要求是一致的。注意 HTTP API 上传的是音频字节（multipart 的 file 字段），不是路径字符串——传路径、URL 或空文件会收到 400，错误信息里会写明收到的字节数和正确用法。

选哪个引擎

Runner语言特点
whisper.cpp多语言ggml .bin 模型；Core ML encoder 可选，缺失时自动走 Metal，不是错误
Qwen3-ASR 0.6B多语言MLX 4-bit，中文与混合语言表现好，可指定语言提示

macai transcribe meeting.m4a --model Whisper-Large-v3-Turbo-Q5 --language zh

curl http://127.0.0.1:11435/v1/audio/transcriptions \

  -F "model=Qwen3-ASR-0.6B-MLX-4bit" \
  -F "language=zh"

音色选择与试听

运行状态页和模型详情里的音色下拉框支持滚轮快速步进：滚轮停下后自动保存为该模型默认音色并试听（可在设置里关掉自动试听）；试听播放随时会被下一次选择打断。命令行对应：

macai voice kokoro-82m-zh              # 列出可用音色
macai voice kokoro-82m-zh zf_001       # 设置默认音色
macai voice Qwen3-TTS-0.6B-CustomVoice-4bit --clear  # 清除默认音色

合成

# CLI：生成 WAV 文件
macai speak "你好，这是本地合成的语音。" --model kokoro-82m-zh --output hello.wav

# Qwen3-TTS 情感指令：逗号后跟情绪描述
macai speak "Vivian, very happy 我们明天见！" --model Qwen3-TTS-0.6B-CustomVoice-4bit

# API
curl http://127.0.0.1:11435/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{"model":"kokoro-82m-zh","input":"你好","voice":"zf_001"}' \
  --output speech.wav

Qwen3-TTS 内置音色：Vivian、Serena、Uncle_Fu、Dylan、Eric、Ryan、Aiden、Ono_Anna、Sohee。

已知限制：speed 参数当前会被校验（0.25–4.0）但对 Qwen3-TTS 实际不生效（上游 mlx-audio 尚无对应参数）；Qwen3-TTS 首版不含流式输出与声音克隆。Kokoro 的 CLI 默认音色是 zf_001。

macai 命令行

macai 只跟 daemon 通信，daemon 没跑它就什么也做不了（会提示启动方法）。全局参数 -a, --addr HOST:PORT 指定 daemon 地址，默认 127.0.0.1:11435。每个子命令的完整参数用 macai <命令> --help 查询。

命令用途
statusdaemon、请求与系统内存概况
list（models）已注册模型及加载状态
ps运行中模型、内存占用、设备与驻留策略
providersProvider 可用性、设备与不可用原因
tasks [id] [--limit N]近期任务列表或单个任务详情
load <path>注册并加载本地模型；--id --type llm|stt|tts --provider --context-length --keep-alive --routing-token
inspect <dir>...目录模型路由诊断，输出 routing token
start <model>加载已注册模型
unload <model>（stop）停止 worker 释放内存，注册保留
remove <model>（rm）删除注册记录，文件保留
rename <model> <new>改 ID（运行中先安全停止）
keep-alive <model> <v>空闲驻留：0 / 5m / 2h / always
pull <repo> <file>从 HuggingFace 下载单文件到模型仓库并注册加载
chat <model> <msg|->一次性对话（无记忆）
run <model>交互式多轮对话（有记忆）
transcribe <file>语音转文字，--model --language
speak <text|->语音合成，--model --voice --output --speed
voice <model> [v] [--clear]查看 / 设置 / 清除 TTS 默认音色
logging [info|debug]查询或调整 daemon 日志级别
serve检查 API server 是否在运行，未运行给出启动提示

HTTP API

/v1/* 面向推理（OpenAI 兼容），/api/* 面向运行时管理。没有鉴权，api_key 填任意占位值。

方法路径用途
GET/health健康检查
GET/v1/models模型列表（含 provider 选择审计字段）
POST/v1/chat/completions对话，支持 SSE 流式与 reasoning_content
POST/v1/audio/transcriptions语音转文字（multipart 音频字节）
POST/v1/audio/speech语音合成，返回 WAV
GET/api/runtime运行状态：内存预算、压力、已加载模型

数据、日志与内存

所有运行时数据都在一个目录里，删掉它等于完整重置（模型会重新下载）：

~/Library/Application Support/MacAIConsole/
├── Models/
│   ├── llm/            # MLX 格式 LLM 目录
│   ├── stt/            # Qwen3-ASR、sherpa-onnx 等 STT 目录
│   └── tts/            # Kokoro、Qwen3-TTS 等 TTS 目录
├── Engines/            # llama.cpp / whisper.cpp 受管引擎
├── Plugins/            # 用户创建的 Script Runner
├── model-settings.json
├── models.db           # SQLite 模型注册表（重启持久）
└── logs/
    ├── aiworkd.log
    └── gui.log
  • 日志按 5 MB 轮换，保留一份 .1。默认 Info；「日志」页或 macai logging debug 开启后，daemon 用同一 request_id 记录每个 HTTP 请求的方法、路径、状态码与耗时——不记查询参数、请求体和响应体。

故障排查

先看「日志」页或 logs/aiworkd.log——错误信息都落在那里。下面是按出现频率排的常见问题。

打开应用提示「已损坏，无法打开」或「未知的开发者」

应用未做签名公证，被 Gatekeeper 拦了，不是真的损坏。终端执行 xattr -cr /Applications/MacAIConsole.app，或在「系统设置 → 隐私与安全性」底部点「仍要打开」。见 安装。

GUI 打开后一直连不上 daemon

GUI 按顺序探测 AIWORKD_PATH → target/release/aiworkd → target/debug/aiworkd。DMG 版自带 daemon，一般不会遇到；源码版请先 cargo build --release --workspace 或手动启动 ./target/release/aiworkd，再用 curl http://127.0.0.1:11435/health 验证。设置页可以关掉「自动拉起」排查冲突。

引擎安装失败

分两种：whisper.cpp 要在本机编译，需预装 Xcode Command Line Tools 和 CMake（brew install cmake），编译耗时属正常；Python 系列（mlx-lm、kokoro、qwen3-asr、qwen3-tts、sherpa-onnx）由 uv 装 wheel，首次安装要联网拉取解释器与依赖，网络不通时配代理或设 MACAI_UV_PYTHON_INSTALL_MIRROR。普通用户建议先装预编译完善的 llama.cpp、mlx-lm、qwen3-asr 或 kokoro。

注册模型被拒绝：「未识别的模型目录」

daemon 靠目录签名识别模型归属的 Runner，识别不了就拒绝，不会乱猜。按提示检查：模型是否下载完整（远端下载中断会缺文件）；对应引擎是否已安装；目录型模型 ID 是否与目录名一致。用 macai inspect <目录> 看具体诊断。确认无误仍不识别的话，说明这类模型还没有对应 Runner，可在「新建 Runner」里自制。

请求返回 backend_crashed

承载该模型的引擎进程崩了（段错误、OOM 都算）。daemon 本身不受影响，其他模型照常服务。在「日志」页看崩溃前后的输出；重试一次通常可恢复。同一模型持续崩溃的话，带上日志提 issue。

模型刚启动，头几个请求报 503

llama.cpp 常驻 server 在初始化模型，最早几秒的请求可能返回 503，稍后重试即可。大模型首次加载慢是正常的，加载完成状态以「运行状态」页为准。

模型下载很慢或失败

「设置 → 模型下载源」切到 https://hf-mirror.com 或自定义源（也可启动时设 AIWORKD_HF_ENDPOINT）。下载支持断点续传（.part 文件），中断后重试会接着传，不用从头来。下载进度在管理页和下载窗口可见，daemon 日志每 5% 记一笔。

内存吃紧，模型总被自动卸载

daemon 的预算默认 min(RAM×0.75, RAM−8GB)，超预算时按 LRU 逐出。可以：调小其他模型的 keep-alive（如 0，用完即卸）；卸掉暂时不用的模型；或在设置页 / AIWORKD_MEMORY_BUDGET 里改预算。正在服务的请求不会被逐出打断（lease 保护）。

temperature 设为 0，两次回答还是不一样

带 session_id 的多轮对话会复用 KV 缓存，Metal 数值精度差异可能让缓存命中后的输出与全量重算偶发分岔。要严格可复现，去掉 session_id 每轮全量计算。

想升级应用

DMG 版在「设置 → 关于」点检查更新：发现新版本后自动下载 DMG、按官方 checksums.txt 做 SHA-256 校验，通过后替换应用并重启（安装前会停掉 aiworkd，新实例按原设置拉起）。默认启动时静默检查一次，设置页可关。开发构建（非 .app bundle）没有更新入口，自己 git pull 重建。

安全与已知限制

安全边界

  • aiworkd 只绑定 127.0.0.1，没有身份认证。别通过端口转发、反向代理把它暴露到局域网或公网——真要远程访问，请在前端加健全的隔离与认证。
  • 任务历史包含 Prompt、转写结果与 TTS 输入文本；原始音频不落盘进历史，日志过滤 token 与模型内容。
  • Runner 以你的用户权限运行本地代码，不是沙箱。脚本 Runner 只装信得过的。

当前限制（截至 2026-09）

  • API 稳定性与跨版本兼容尚无承诺，升级可能需要调整调用方。
  • Qwen3-TTS 的 speed 参数校验但不生效；流式合成与声音克隆未支持。
  • sherpa-onnx 仅支持中文。
  • whisper.cpp 引擎需本机编译（CMake），是唯一有编译依赖的引擎。
  • 完整第三方 Runner package 的导入、更新与分发还在规划中，当前以本机创建的 Script Runner 为主。

漏洞报告与完整威胁模型见 SECURITY.md；贡献指引见 CONTRIBUTING.md。行为细节与设计理由以仓库 决策记录 为准。
